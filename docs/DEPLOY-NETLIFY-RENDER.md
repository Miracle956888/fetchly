# Deploy Fetchly to Netlify (frontend) + Render (API)

Exact click-path for the split-origin topology. **Order matters:** deploy the API
first so you know its URL, then the frontend, then point the API's CORS back at the
frontend URL.

Everything below assumes the repo is on GitHub and you select the branch
`arena/01a09fc7-fetchly` in both dashboards (or merge it to `main` first and use `main`).

---

## Step 1 — API on Render

1. https://render.com → **New +** → **Blueprint** → choose `Miracle956888/fetchly`.
2. Pick branch `arena/01a09fc7-fetchly`. Render reads `render.yaml` and creates the
   `fetchly-api` web service from `server/Dockerfile` (bundles FFmpeg + yt-dlp).
3. Render prompts for the `sync: false` variables:
   - `CLIENT_URL` → put a **placeholder** for now, e.g. `https://placeholder.netlify.app`
     (you will replace it in Step 3 once Netlify exists).
   - `ADMIN_EMAIL` → your real admin email.
   - `JWT_SECRET` and `ADMIN_PASSWORD` are auto-generated by Render
     (`generateValue: true`). **Copy `ADMIN_PASSWORD` from the service's Environment
     tab** — you need it to sign in.
   - `ALLOW_EPHEMERAL_STORAGE=true` is pre-set: the free tier has no MySQL/Redis, so
     data resets on sleep/redeploy. See Step 5 to make it persistent.
4. Deploy. When finished, copy the service URL, e.g. `https://fetchly-api.onrender.com`.
5. Verify (first hit can take ~30–60 s on the free tier while it wakes):

   ```
   https://fetchly-api.onrender.com/api/v1/health
   → {"status":"ok","uptime":…,"persistence":"memory"}
   ```

## Step 2 — Frontend on Netlify

**Option A — connect the repo (recommended):**

1. https://app.netlify.com → **Add new site** → **Import an existing project** →
   GitHub → `Miracle956888/fetchly` → branch `arena/01a09fc7-fetchly`.
2. `netlify.toml` supplies the build command
   (`npm ci && npm run build -w client`) and publish dir (`client/dist`) automatically.
3. **Site configuration → Environment variables**, add:

   | Variable | Value |
   | --- | --- |
   | `VITE_API_ORIGIN` | your Render URL, e.g. `https://fetchly-api.onrender.com` |
   | `VITE_SITE_URL` | *leave empty for the first deploy* |
   | `NODE_VERSION` | `20` (a `.nvmrc` is also committed; either works) |

4. Deploy. Copy the site URL, e.g. `https://fetchly-dreamy-1234.netlify.app`.
5. Now set `VITE_SITE_URL=https://<your-site>.netlify.app` (and optionally
   `VITE_CONTACT_EMAIL=dmca@yourdomain.com`), then **Deploys → Trigger deploy →
   Clear cache and deploy site**. This bakes the canonical link, Open Graph/Twitter
   tags, `robots.txt` and `sitemap.xml` with your real domain.

**Option B — Netlify Drop (no repo connection):**

```bash
VITE_API_ORIGIN=https://fetchly-api.onrender.com npm run build -w client
```

then drag `client/dist` onto https://app.netlify.com/drop. The `dist/_redirects`
file shipped in the build gives you SPA deep-link routing without `netlify.toml`.
(Set `VITE_SITE_URL` and rebuild once you know the dropped site's URL.)

## Step 3 — Point the API's CORS at the frontend

Render → `fetchly-api` → **Environment** → set:

| Variable | Value |
| --- | --- |
| `CLIENT_URL` | `https://<your-site>.netlify.app` (replace the placeholder) |
| `COOKIE_SAMESITE` | keep `strict` |

Saving triggers a redeploy.

**Why `strict` is correct here:** the frontend and API are on different sites, so a
`SameSite` cookie would never be sent. The client detects this (it was built with
`VITE_API_ORIGIN`) and authenticates with a bearer token instead — no third-party
cookie involved, so Safari/Chrome cookie blocking cannot break the admin console.
Only switch to `none` if you specifically want cookie-based cross-site sessions.

Optional extra origins (e.g. a preview URL): comma-separate them in `CORS_ORIGINS`.

---

## Step 4 — Verify the live deployment

- `https://<your-site>.netlify.app/` → homepage loads, platform chips render.
- Paste a public TikTok/YouTube link → analysis responds. From datacenter egress some
  platforms bot-check and return an honest `CONTENT_UNAVAILABLE`; that is expected and
  not a deployment fault.
- `https://<your-site>.netlify.app/downloads` (hard refresh) → 200, not 404 (SPA fallback).
- `https://<your-site>.netlify.app/admin/login` → sign in with `ADMIN_EMAIL` +
  `ADMIN_PASSWORD` → dashboard, jobs and stats load. This exercises the cross-origin
  bearer auth end to end.
- `https://fetchly-api.onrender.com/api/v1/health` → 200.

---

## Step 5 — Make it persistent (optional, leaves the free tier)

1. Provision MySQL 8 + Redis (Render managed, Railway, Aiven, PlanetScale…).
2. Render → Environment → set `DATABASE_URL`, `REDIS_URL`, and
   `ALLOW_EPHEMERAL_STORAGE=false`.
3. Redeploy. The container entrypoint runs `prisma migrate deploy` automatically on
   boot; existing data is never dropped.
4. Custom domain: add it in Netlify **Domain management** (TLS is automatic), then set
   `VITE_SITE_URL=https://yourdomain.com` (Netlify env, redeploy) and
   `CLIENT_URL=https://yourdomain.com` (Render env, redeploy).

---

## Free-tier caveats

- Render free web services sleep after ~15 min idle; the first request after a sleep
  is slow while the container boots.
- With `ALLOW_EPHEMERAL_STORAGE=true`, download history and admin stats reset whenever
  the service restarts. Step 5 removes that.
- yt-dlp/FFmpeg are inside the Docker image, so the media engine works on Render even
  though a bare VPS would need them installed manually.
